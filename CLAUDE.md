## Architecture

- `run.py` — entrypoint. Loads `.env`/`.env.sh`, wires `server/website.py` (page routes) and `server/backend.py` (API routes) onto the Flask app from `server/app.py`.
- `server/app.py` — Flask app, CORS (open to all origins), `/` (redirects to `/chat/`), `/chat/` (renders the chat UI), `/api/chat` (the public conversation API). No login/auth gate (Google OAuth was removed) and no API credential check or rate limit either — anyone who has the URL can call `/api/chat` or `/backend-api/v2/conversation`.
- `server/backend.py` — `Backend_Api._conversation`: builds the system prompt, calls `ask_from_llm` to decide if fresh retrieval is needed, then streams a Gemini answer in two phases. Every call passes the system prompt as Gemini's `system_instruction`; the contents are the chat history as sent, then one user turn from `prompt_templates.build_answer_turn` (retrieved context + question + that phase's instruction):
  - Path choice: if the classifier says no search is needed, one complete answer. Otherwise `ragwithsearch.judge_kb_coverage` (flash-lite) rates how much of the answer the Run of Play hits hold as of today: `full` -> one complete answer from them (no web search); `partial` -> Phase 1 + Phase 2 below; `none` -> no draft: the status line straight away, then one complete answer from the web search plus the Run of Play hits. Phase 1 can also reply `NO_RELEVANT_CONTEXT` (held back like `NO_NEW_UPDATES`), which switches to that same combined answer.
  - Phase 1: fast draft using whatever context is available, then a `## HALFTIME!!! <status>` line (e.g. "Checking the latest news"). The clients show only the status, as a grey shimmer line under the draft with a live seconds counter, and drop it once Phase 2 text arrives or the answer ends. The `## HALFTIME!!!` prefix is the wire marker; changing it would make older embeds show the raw line.
  - Phase 2: re-runs retrieval with `force_search=True` and streams a refinement continuing the draft. If Gemini says `NO_NEW_UPDATES`, or there's no new context, the answer simply ends on the draft.
- `ragwithsearch.py` — retrieval core:
  - `classify_and_build_query` — Gemini (`gemini-2.5-flash-lite`) + heuristic keyword classifier decides `search_required` and builds a keyword-rich query; resolves follow-up pronouns using recent conversation history. Award/title questions without a year ("Who won the Ballon d'Or?") count as current.
  - `judge_kb_coverage` — flash-lite rates the Run of Play hits `full` / `partial` / `none` for the question as it stands today (`prompt_templates.build_relevance_check_prompt`); `partial` if the check fails. For a latest-news question whose hits are all ARCHIVE (older than 30 days) it returns `none` without a model call. It and the classifier run at temperature 0 (`DECISION_CONFIG`).
  - `build_news_context` (formerly `formatted_prompting`) — first call (Phase 1): always returns the top Run of Play chunks from `kb_search.hybrid_search` (searched with the classifier's query plus the user's own question), labeled by age (`RUN OF PLAY CONTEXT` within 30 days, `RUN OF PLAY ARCHIVE ... background only` beyond), with the classifier's `search_required` (whether they're enough is `judge_kb_coverage`'s call). Second call (Phase 2, Phase 1's context passed in): web search via a self-hosted SearXNG instance (`SEARXNG_URL` env var, `engines=bing news`, `time_range=month` for latest-news questions — see below), scrapes up to 2 results with `crawl4AI.py` (BM25-ranked chunks), and adds Bing's headline + snippet for up to 4 more, including pages that block the scraper. ISO dates the classifier put in the query are stripped before searching. Always returns `(context, search_required, formatted_query)`.
- `kb_search.py` — hybrid search over the Run of Play chunks: Pinecone cosine (top 30) + BM25 over every chunk (top 30, title and Wix tag words counted double, stemmed and accent-folded, unknown query words fuzzy-matched to the closest indexed word with the same first letter) + query-word coverage + exponential recency decay, fused per chunk (dense and BM25 min-max normalised across candidates). Keyword-only hits get their real cosine from their fetched Pinecone vectors. Weights per question type: latest-news 0.30/0.20/0.10/0.40 (recency half-life 30 days), otherwise 0.45/0.25/0.15/0.15 (half-life 365 days). Max 2 chunks per article. The BM25 index is a snapshot of all chunk metadata pulled from Pinecone (`list` + parallel `fetch`, ~10s, ~30MB) in a background thread, started by `run.py` at startup and refreshed every 6h; until it's ready, search ranks Pinecone's candidates alone. Logs every pick's signals as `[OffTheBar kb] ...`.
- `kb_google.py` — Pinecone-backed knowledge base. Embeddings computed locally with `fastembed` (ONNX build of `BAAI/bge-small-en-v1.5`, the same model the index was built with; no API key), index name `football-docs`. Exposes `embed_texts`/`get_pinecone_index` as public entry points (used by `ingest_kb.py`) alongside `search_pinecone` (used by the live retrieval path).
- `ingest_kb.py` — ingestion pipeline: pulls posts from the Wix blog's REST API (`GET https://www.wixapis.com/v3/posts`, `fieldsets=CONTENT_TEXT` for plain text), chunks each post, embeds each chunk with the post title in front via `kb_google.embed_texts`, stores the title and tag labels (`list_wix_tags`, `GET /v3/tags`) in each vector's metadata, and upserts into Pinecone via `kb_google.get_pinecone_index`. Runs daily as the `offthebar-ingest-kb` Cloud Run Job (see `CLOUDRUN.md`), not as part of the request path.
- `prompt_templates.py` — full answers (complete-context and Phase 2) end with their follow-up prompts in a fixed `Ask next:` + list block (`FOLLOW_UP_FORMAT`); the clients cut it from the text and show the items as buttons that send the question. Also: system prompt (football-pundit persona, "controlled poetic flair" rules) and prompt builders for first draft / refinement / search classification.
- `gemini_utils.py` — every Gemini call goes through `call_gemini_with_key_retry()`. Keys (`GEMINI_API_KEY`, `GEMINI_API_KEY_2`, ... or `GEMINI_API_KEYS`) are tried in a fixed order, not round-robin: the free-tier keys named in `GEMINI_FREE_TIER_KEYS` (here `2`) first, then the paid ones (here `GEMINI_API_KEY`). A call moves on to the next key on quota exceeded, a bad/revoked key, or a server error (500/503 "overloaded", timeouts), but not on a 400. A key that hit a quota is skipped for that model until it should be back (daily quotas: midnight Pacific; rate limits: the `retryDelay` Gemini sends, else 60s); a bad key for an hour. Each call logs its key and token usage (`[OffTheBar Gemini] gemini-2.5-flash via key #1 (paid): input ..., output ..., thinking ... tokens`). Uses the `google.genai` SDK (`genai.Client`).
- `evals/` — pipeline evaluation: `cases.json` (20 dated questions with expected classification, search query, latest-news flag, retrieved Run of Play titles, coverage, answer path and answer content) and `run_evals.py` (runs them through the real pipeline; routing stages by default, `--answers` for real `/api/chat` answers; prints pass rates per stage and the run's Gemini cost; JSON reports in `evals/reports/`, gitignored). See `evals/README.md`. Run it before deploys and after changes to retrieval, prompts or routing.
- `client/` — static frontend (`index.html`, `chat.js`, `style.css`) served by this Flask app at `/chat/`.
- `wix/` — the therunofplay.com chat page's code, which lives in the Wix editor: Velo page code (`offthebar-page.js`) and the two HTML embeds, `chatHtml` (`chat-iframe.html`) and `inputHtml` (`input-iframe.html`). The repo is the source of truth; changes only go live once pasted into the editor and published. `wix/preview/` runs all three locally against a mock, local or live backend (`cd wix && python3 -m http.server 8000`, open `/preview/`). `wix/README.md` covers the preview, publishing steps and the page ↔ embed message protocol.
- `Dockerfile` / `.dockerignore` — the Cloud Run image: Python 3.11-slim, Playwright/Chromium, NLTK `punkt`/`punkt_tab`, the embedding model baked into `/opt/fastembed` (`FASTEMBED_CACHE_PATH`), served by `gunicorn` (1 worker, 8 threads). `.dockerignore` keeps `.env` and `chat_logs/` out of the image.
- Config: `config.json` (host/port/proxy), `config_env.py` (`require_env` helper, loads `.env`), `.env.example` lists the env vars. On Cloud Run, secrets come from Secret Manager (`CLOUDRUN.md`); a `.env` file is only used for local dev and the legacy PythonAnywhere host (`PYTHONANYWHERE.md`).
